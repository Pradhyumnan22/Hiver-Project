# Hiver AI Customer Support Agent

A reproducible, grounded AI customer-support agent and rigorous evaluation pipeline built on Kaggle's Customer Support on Twitter dataset.

## Architecture Overview

```
Customer Message
       │
       ▼
┌───────────────────────────────┐
│ 1. Intent Classification      │  ◄── Trivial Majority, TF-IDF + Logistic Regression, & LLM Classifier
└──────────────┬────────────────┘
               │
               ▼
┌───────────────────────────────┐
│ 2. Historical Retrieval       │  ◄── FAISS Semantic Index with Relevance Threshold & Leakage Exclusion
└──────────────┬────────────────┘
               │
               ▼
┌───────────────────────────────┐
│ 3. Deterministic Escalation   │  ◄── Rules Engine: High-Risk, Low Retrieval, Out-of-Scope Intents
└──────────────┬────────────────┘
               │
         ┌─────┴─────┐
         ▼           ▼
   [auto_handle]   [escalate]
         │           │
         ▼           ▼
  Grounded Reply  Human Triage Reason
```

## Features

- **Strict Leakage Prevention**: Held-out evaluation and golden sets are strictly segregated before building retrieval indices or training classifiers.
- **Deterministic Escalation Engine**: Independent safety and policy layer; the LLM does not decide its own safety.
- **Multi-Tier Baseline Comparisons**: Evaluated against Majority-class baseline and TF-IDF + Logistic Regression baseline.
- **LLM-as-Judge & Human Agreement**: Documented rubric measuring groundedness, relevance, helpfulness, consistency, and safety with Cohen's Kappa agreement tracking.
- **Zero-Secret Architecture**: Full test suite and baseline evaluations run offline without external API keys or proprietary servers.

## Intent Taxonomy & Golden Evaluation Benchmark

Derived from customer interaction patterns on `AmazonHelp`:
1. `order_status_delivery`: Shipping status, late packages, courier inquiries.
2. `returns_refunds`: Return policies, refund timelines, locker drop-offs.
3. `damaged_defective_item`: Broken, missing, expired, or incorrect products.
4. `account_access_security`: Login issues, unauthorized charges, OTP authentication.
5. `subscription_digital`: Prime memberships, video streaming, digital billing.
6. `product_inquiry_availability`: Item specifications, stock availability, compatibility.
7. `other_unknown`: Unclear, ambiguous, or out-of-domain inquiries.

- **Annotation Guide**: Documented in [`docs/annotation_guide.md`](docs/annotation_guide.md).
- **Golden Set Status**: 200 unique held-out examples were reviewed row by row
  in four semantic-review batches. Provenance is retained in
  `data/annotations/golden_review.csv`; records are explicitly marked
  `ai_manually_reviewed`, not human-verified.


## Data Preparation & Preprocessing

The preprocessing pipeline targets **AmazonHelp** from the 3M-tweet dataset:
- **Conversation Linkage**: Matches brand response back to parent customer tweet using `in_response_to_tweet_id`.
- **Privacy & Anonymization**: Masks user handles (`@user`), URLs (`<URL>`), emails (`<EMAIL>`), and phone numbers (`<PHONE>`).
- **Leakage Prevention**: Strictly splits partitions by customer `author_id` (80% dev, 20% eval) ensuring zero customer or conversation overlap between the knowledge base and evaluation set.

To reproduce dataset preparation:
```powershell
python scripts/prepare_dataset.py --max-rows 150000 --sample-size 100
```
- Sample fixture: `data/sample/sample_pairs.json` (committed to repository)
- Processed splits: `data/processed/dev_pairs.json` (5,124 pairs) and `data/processed/eval_pairs.json` (1,292 pairs)

## Historical Retrieval Calibration

The FAISS index uses normalized `all-MiniLM-L6-v2` embeddings and exact inner
product search. The production threshold is **0.65**, selected using 500
development-only queries split by customer author:

- Target same-intent proxy precision: **80%**
- Measured proxy precision at 0.65: **81.51%**
- Development coverage at 0.65: **71.40%**
- Final index: **4,792** unique normalized customer messages

Same-intent agreement is only a weak-supervision relevance proxy, not a human
relevance judgement. The complete threshold curve and limitation are saved in
`reports/retrieval_calibration.json`.

```powershell
python scripts/calibrate_retrieval.py
python scripts/build_knowledge_base.py
```

The build excludes evaluation authors, tweet IDs, normalized evaluation text,
and duplicate indexed text. Model download and index files are intentionally
excluded from Git.

## Grounded Agent and Escalation

`src.agent.run_support_agent` is the single pipeline entry point. It:

1. Validates an LLM intent classification against the seven-intent enum.
2. Retrieves traceable historical cases above the calibrated threshold.
3. Applies deterministic escalation rules before generation.
4. Generates a structured draft only for eligible messages.
5. Verifies cited evidence IDs and rejects unsupported action/status claims.

The deterministic policy escalates high-risk language, unsupported intents,
account-security cases, transaction-specific requests, repeated unresolved
complaints, insufficient evidence, malformed model output, API failures, and
unsafe drafts. It does not use an LLM-provided confidence score.

Historical responses are examples of past handling—not verified resolutions
or current policy. Replies are offline drafts and are never published to real
customers. Unit and integration tests use deterministic fake LLM responses,
so no API credential is required.

## Agent Evaluation and LLM Judge

The live evaluation command measures intent classification, escalation,
retrieval coverage, reply quality, latency, and token usage on fixed golden
inputs:

```powershell
python scripts/evaluate_agent.py
```

Use `--limit N` only for smoke tests and `--skip-judge` to evaluate the agent
without reply-quality judging. The five-criterion 1–5 rubric is documented in
`docs/evaluation_rubric.md`.

The 200-example live run is saved in `reports/agent_results.json`:

- Classification accuracy: **76.00%**; macro F1: **0.7368**
- Escalation F1: **0.6909**; escalation accuracy: **57.50%**
- Retrieval coverage: **68.00%**
- Judge mean scores on 80 drafts: groundedness **3.25**, relevance **4.89**,
  helpfulness **3.29**, consistency **4.30**, safety **5.00**
- Wall time: **83.2 seconds**; agent tokens: **107,943**; judge tokens: **70,680**

A blinded 30-response subset was scored by `cursor-ai-rubric-review-v1`.
Pooled exact agreement with the judge is **50.67%**, within-one agreement is
**88.00%**, and quadratic-weighted Cohen's kappa is **0.4559**. This is
AI–judge agreement, not independent human validation. USD cost is omitted
because pricing is not assumed.
